# Статистика клана Clash of Clans

Сайт со статистикой клана по КВ, ЛВК и рейдам столицы. Данные обновляются сами каждые 15 минут, хостинг бесплатный (GitHub Pages + GitHub Actions).

- Вся статистика хранится по тегу игрока. Если игрок вышел из клана и вернулся, его история сохраняется.
- На сайте видны только текущие участники. Вышедшие скрыты, но их данные остаются в файлах.
- Подробная статистика начинается с момента запуска. Рейды API отдаёт и за прошлые выходные, поэтому их история появится сразу.

## Настройка (один раз, примерно 15 минут)

### 1. Ключ API Supercell

1. Зайдите на https://developer.clashofclans.com и зарегистрируйтесь. Подойдёт любая почта.
2. Откройте **My Account**, затем **Create New Key**.
3. Заполните поля:
   - **Name / Description**: любое, например `clan-site`;
   - **Allowed IP Addresses**: `45.79.218.79`. Это IP прокси RoyaleAPI, через который ходит сборщик.
4. Скопируйте получившийся длинный **Token**.

### 2. Репозиторий на GitHub

1. Создайте на https://github.com/new **публичный** репозиторий, например `clan-stats`. Для бесплатного GitHub Pages он должен быть публичным.
2. Нажмите **Add file → Upload files** и перетащите файлы из архива: `index.html`, `README.md` и папку `scripts`. Папку `data` создаст сборщик сам. Затем нажмите **Commit changes**.
3. Файл расписания загрузите отдельно, потому что папки с точкой в начале имени часто не перетаскиваются:
   - нажмите **Add file → Create new file**;
   - в поле имени введите `.github/workflows/update.yml`;
   - вставьте содержимое файла `update.yml` из архива и нажмите **Commit changes**.

### 3. Секрет с ключом

1. В репозитории откройте **Settings → Secrets and variables → Actions → New repository secret**.
2. В поле **Name** введите `COC_TOKEN`, в поле **Secret** вставьте токен из шага 1 и сохраните.

Тег клана уже прописан (`#280L809U9`). Чтобы поменять его, на той же странице откройте вкладку **Variables** и добавьте переменную `CLAN_TAG`.

### 4. Включить сайт

1. Откройте **Settings → Pages**.
2. В разделе **Build and deployment** выберите **Source: Deploy from a branch**, затем **Branch: main** и папку **/(root)**. Нажмите **Save**.
3. Через минуту сайт будет доступен по адресу `https://ВАШ_НИК.github.io/clan-stats/`.

### 5. Первый запуск

1. Откройте вкладку **Actions**.
2. Если GitHub попросит разрешение, нажмите **I understand my workflows, go ahead and enable them**.
3. Слева выберите **Обновление статистики**, затем нажмите **Run workflow → Run workflow**.
4. Через минуту должна появиться зелёная галочка, а в папке `data/` — файлы с данными.

Дальше всё работает само.

## Если что-то не так

| Проблема | Что делать |
|---|---|
| Красный крестик в Actions, в логе `403` | Ключ создан не для IP `45.79.218.79` или вставлен с пробелом. Создайте новый ключ и обновите секрет. |
| На сайте «Журнал войн клана закрыт» | В игре откройте настройки клана и включите «Журнал войн: открытый». |
| Сайт пишет «Данных пока нет» | Сборщик ещё не отработал. Запустите его вручную (шаг 5). |
| GitHub прислал письмо, что расписание отключено | Откройте Actions и нажмите **Enable workflow**. |

## Как считается статистика

- **Пропуск в КВ и ЛВК**: атака, которую игрок не сделал в законченной войне, хотя был в составе.
- **Пропуск рейда**: выходные, когда игрок был в клане все выходные, но не сделал ни одной атаки.
- **Недобил**: игрок атаковал в рейдах, но использовал не все атаки.
- **Новые звёзды**: звёзды, которые атака реально добавила к счёту войны.
- **Оборона ★**: сколько звёзд в среднем снимают с базы игрока. Чем меньше, тем лучше.
- Если клан начал новую войну сразу после окончания предыдущей, сборщик мог не застать финал. Тогда итог берётся из журнала войн, а пропуски засчитываются, только если последний снимок был сделан меньше чем за час до конца войны.

## Файлы

- `scripts/collect.py`: сборщик на Python, только стандартная библиотека.
- `data/*.json`: накопленные данные (игроки, войны, ЛВК, рейды).
- `index.html`: сам сайт (стили и скрипт внутри).
- `.github/workflows/update.yml`: расписание запуска.

## Несколько кланов

- Список кланов хранится в `_admin/clans.json`. Папки с «_» GitHub Pages не публикует, поэтому со страниц сайта список не виден.
- У каждого клана своя ссылка с его тегом: `https://<ник>.github.io/clan-stats/?c=280L809U9`. Страница клана загружает только данные этого клана, списка других кланов в ней нет.
- Ссылка без параметра открывает основной клан.
- Управление — отдельная страница без ссылок с сайта. Кнопки на ней ведут на запуск «Управление кланами» в Actions; запустить его может только владелец репозитория.
- Действия: `add` (добавить), `collect-off` / `collect-on` (сбор), `hide` / `show` (страница клана), `default` (основной клан), `remove` (убрать из списка, данные остаются).
- Пока сайт на GitHub, репозиторий публичный: файлы технически можно найти в самом репозитории. На своём сервере список кланов и страница управления будут закрыты паролем.
